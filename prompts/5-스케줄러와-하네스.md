  계획에서 정해야 할 것들이다.

  1. 스케줄러 구현 방식. `@nestjs/schedule`을 쓸지 직접 둘지 후보를 표로 비교하고 골라줘. 버전과 NestJS 12 호환은 원문을 직접 열어 확인해줘. 인스턴스가 둘
  이상으로 늘었을 때 같은 정합화가 두 번 도는 문제를 어떻게 막을지도 같이 정해줘. 가정 행 잠금이 이미 있으니 그것으로 충분한지 판단해줘.

  2. 정합화 주기. 4.4절은 "주기적으로"라고만 한다. 매분 도는 것과 끼니의 식단시간에 맞춰 도는 것을 비교하고, 서버가 오래 멈춰 있다 올라온 경우와 식단시간이
  바뀐 경우를 같이 따져줘.

  3. 브리프 시각. `alert_settings.brief_time`은 가정마다 다르고 도구로 바뀐다. 고정 크론으로 매분 확인할지, 설정이 바뀔 때 잡을 다시 걸지 정해줘.

  4. 브리프 내용을 어디서 만들지. 5장의 구성 요소는 이미 있는 도메인 함수들의 조합이다. `projectCalendar`, `summarizeStock`, `batchesNeedingExpiryAlert`,
  `forecastShortage`, `introductionStatuses`가 그것이고, `lastPlannedMealDate`·`needsObservation`·`nextExposureNumber`는 1단계에서 브리프를 보고 만들었지만
  아직 아무도 부르지 않는다. 새 도메인 함수를 더할지, 애플리케이션 읽기 모델로 조합할지 정해줘.

  5. "확인 필요" 항목을 모으는 방법. 보류된 차감(`HeldDeduction`)은 저장하지 않기로 했고 그 이유가 `reconcile.service.ts` 주석에 있다. 브리프가 그것을 읽으려면
  정합화를 다시 돌려야 하는데, 그러면 읽기 도구가 쓰기 트랜잭션을 타게 된다. 이 구멍을 어떻게 메울지 정해줘. 반응 미기록, 중량 불일치 배치, 조합 위반, 식단
  잔여 일수도 같은 항목에 들어간다.

  필요하면 스키마까지 정해줘.

  기존 방식을 유지해줘.

  - 도메인 코어(`src/domain`)는 프레임워크, DB, 시스템 시계에 의존하지 않게 둔다. 지금까지 세 단계 모두 한 줄도 바꾸지 않았다.
  - 애플리케이션 계층은 NestJS를 모른다. 서비스는 생성자에 포트를 받는 평범한 클래스이고 모듈이 `useFactory`로 조립한다. 스케줄러도 애플리케이션을 호출하는
  어댑터로 두고, 재고 규칙을 그 안에 다시 쓰지 않는다.
  - 현재 시각은 `ClockPort`로만 들어온다. 벽시계는 `now()`·`today()`, 절대 시각은 `instant()`다.
  - 테스트는 지금 수준으로 꼼꼼하게 쓴다. 규칙을 한국어로 서술하는 이름을 쓰고, 마지막에 핵심 로직을 일부러 고장 내 테스트가 잡는지 확인한다. 3단계에서는
  11건을 넣어 전부 잡히는 것을 확인했다.

  검증에 대해 분명히 해 둔다. "자체 검증하고 진행해"는 확인을 건너뛰라는 뜻이 아니라 책임지고 직접 확인하라는 뜻이다. 문서에 넣는 인용문과 링크는 원문을 직접
  열어 확인하고, 설정 파일에 쓰는 패키지 이름은 실제 트리에서 확인해줘. 서브에이전트 보고는 단서이지 근거가 아니다.

  알아 두실 점

  - 통합 테스트에는 Docker가 필요합니다. `docker compose up -d`로 로컬 PostgreSQL(포트 55432)을 띄우면 됩니다. 통합 테스트 자체는 Testcontainers가 따로
  띄우므로 이 컨테이너는 마이그레이션 개발용입니다.
  - `pnpm test`는 단위만(Docker 불필요), `pnpm test:int`은 통합, `pnpm test:cov`는 둘 다 돌며 계층별 임계값을 검사합니다. `pnpm test:e2e`는 `DATABASE_URL`과
  살아 있는 PostgreSQL이 필요합니다.
  - Prisma 7은 `migrate`가 `generate`를 자동 실행하지 않습니다. 스키마를 바꾸면 `pnpm db:migrate` 뒤에 `pnpm prisma:generate`를 따로 부릅니다. 스키마 언어에
  CHECK와 부분 인덱스가 없어 `migrate dev --create-only`로 SQL을 만든 뒤 손으로 덧붙입니다.
  - MCP 서버에 붙으려면 토큰이 필요합니다. `pnpm member-token --household 재하네 --member 엄마 --label "..."`으로 발급하고, `--list`와 `--revoke`가 있습니다.
  - `.npmrc`의 `minimumReleaseAge`가 7일이라 갓 나온 버전은 설치되지 않습니다. 범위를 적을 때 공개일을 먼저 확인해 주세요.
  - 패키지를 설치하게 되면 직전에 목록과 해석된 버전, lock 파일 변경을 보여 주고 확인을 받아주세요.
  - 커밋은 종류별로 나눠 주세요. push는 제가 직접 하거나 별도로 지시하겠습니다.
