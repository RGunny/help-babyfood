+## 12. 합침 재료 마이그레이션을 적용하고 쌀오트밀로 전환한다
+
+- [ ] 배포 직후 바로 운영 컨테이너에서 `ingredient_constituent` 마이그레이션을 적용한다.
+- [ ] Claude Code에서 `register_blend_ingredient`로 `쌀오트밀`을 등록한다. 분류 `base`, 1회분 50g, 구성 재료 쌀과 오트밀이다.
+- [ ] `register_menu`로 `쌀오트밀합침죽`(쌀오트밀 1개)을 등록한다. **`update_menu`로 기존 `쌀오트밀죽`의 구성을 바꾸지 않는다.**
+- [ ] 합침 큐브를 만든 날 `register_cooked_batch`로 `쌀오트밀` 50g 배치를 입고한다.
+- [ ] 낱개 쌀 큐브와 오트밀 큐브가 끝나는 날부터의 예정 식단을 `update_planned_meal`로 `쌀오트밀합침죽`으로 옮긴다. 남는 낱개 큐브는 실사 조정이나 폐기로 정리한다.
+- [ ] `get_alert_settings`로 읽은 뒤 `update_alert_settings`로 임계개수에서 쌀과 오트밀을 빼고 쌀오트밀을 넣는다.
+
+ADR 0011이 합침 재료의 구성 재료 목록으로 `ingredient_constituent` 테이블을 더한다. 6번이 말하듯 Railway 서비스에 배포 전 명령이 아직 없어서, 마이그레이션이 든 커밋을 push하면 배포는 시작되지만 마이그레이션은 돌지 않는다. 배포 뒤 사람이 돌린다.
+
+```bash
+railway ssh "cd /app && pnpm db:deploy"
+```
+
+배포 직후에 바로 돌린다. 마이그레이션이 적용되기 전에 뜬 서버는 재료를 적재할 때 없는 테이블을 읽어 상태 적재가 실패한다. 그동안 정합화와 브리프가 멈춘다.
+
+그 뒤는 Claude Code에서 한다. 먼저 `register_blend_ingredient`로 `쌀오트밀`을 등록한다. 분류는 `base`, 1회분은 50g, 구성 재료는 쌀과 오트밀이다. 구성은 등록한 뒤 바꿀 수 없으므로(ADR 0011) 이름과 구성 재료를 확인하고 등록한다.
+
+이어서 `register_menu`로 `쌀오트밀합침죽`(쌀오트밀 1개)을 등록한다. `update_menu`로 기존 `쌀오트밀죽`의 구성을 바꾸지 않는다. 바꾸면 지난 끼니의 쌀과 오트밀 차감이 전부 되돌려지고, 그 끼니마다 쌀오트밀 차감이 보류로 쌓인다(ADR 0011). 메뉴 이름에 괄호를 쓰지 않는다. 식단표 가져오기가 괄호를 메모로 읽는다(기획안 4.1절).
+
+합침 큐브를 만든 날 `register_cooked_batch`로 `쌀오트밀` 50g 배치를 입고한다. 그리고 낱개 쌀 큐브와 오트밀 큐브가 끝나는 날부터의 예정 식단을 `update_planned_meal`로 `쌀오트밀합침죽`으로 옮긴다. 2026-10-06 기준 재고는 쌀 30g 큐브 4개와 오트밀 10g 큐브 2개다. 식단을 옮긴 뒤 남는 낱개 큐브는 `adjust_stock_by_count`나 `discard_batch`로 정리한다.
+
+마지막으로 임계개수를 고친다. 전환 뒤 쌀과 오트밀은 식단에 없지만 임계개수가 걸려 있어, 빼지 않으면 재고 알람의 임계개수 이하 표에 계속 나온다. `get_alert_settings`로 지금 설정을 읽은 뒤 `update_alert_settings`로 쌀과 오트밀을 빼고 쌀오트밀을 넣는다. 통째로 갈아 끼우는 도구라 읽지 않고 쓰면 설정이 지워진다(기획안 7장).
+
+이 작업이 사람 몫인 이유는 둘이다. 마이그레이션은 운영 DB에 쓰는 일이고(AGENTS.md 검증 절), 언제 합침 큐브를 만들고 낱개 큐브가 언제 끝나는지는 냉동고를 보는 사람만 안다.
